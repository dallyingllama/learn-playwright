Guidelines for DemoQA

Project Structure

The DemoQA project follows a specific structure to ensure clarity and maintainability. Below is an overview of the key directories and their purposes:

Directory

Purpose

local/repo

.env

Environment-specific .env files used by Playwright config through TEST_ENV.

repo

.github

CI workflow and helper scripts for test execution, docs publishing, and report publishing.

repo

data

Reusable test data builders and fixtures used by specs and helpers.

repo

docs

Publishable Antora docs source and site assets.

repo

history

Generated GitHub Pages report/history workspace used during publish steps.

local

node_modules

Installed dependencies for tests, scripts, and documentation tooling.

local

page-objects

Page models, shared page behavior, and component abstractions.

repo

playwright-report

Local Playwright HTML report output.

local

project-docs

Internal planning and workflow documents for ongoing repository work.

repo

test-results

Local Playwright artifacts for latest runs (traces, screenshots, and output).

local

tests

End-to-end and unit-style Playwright specs.

repo

utils

Shared helper utilities for navigation, annotations, and common test support.

repo

Naming Conventions

The following table outlines the basic naming conventions used in the DemoQA project. These conventions help maintain consistency and readability across the codebase.

Topic Description Example

Files and folders

Use kebab-case names.

book-data.ts, page-objects/

Types, classes, and interfaces

Use PascalCase names.

BookData, BookDataBuilder, NavigablePage

Variables and functions

Use camelCase names.

bookData, buildBookData, assertOnPage()
